
스프링

Internet : 도로
Web : 트럭

결합도 낮추는 기능 IOC, DI
응집도 높이는 기능 AOP

IOC :  객체를 만드는 제어의 주체가 바뀐다 (개발자 <-> 스프링)
	ㄴ> 1. 자동 생성 (디폴트)패키지 안에 있거나
	ㄴ> 2. 객체 필요 클래스 위에 객체 생성 명령하는 어노테이션 ( ex) @Component )
	ㄴ>> 스프링 프로젝트를 run 하면 객체를 자동 생성해준다

DI : IOC로 스프링이 만들어준 객체를 우리가 선언한 객체에 넣어주는 것
	ㄴ> 생성자 주입방식(권장) -> (@Autowired)이미 만들어진 객체를 매개변수로 전달
	ㄴ> 그밖의 주입방식들 (수정자.필드.일반 매서드 주입방식)

bean : 객체 (콩)

URL 요청 : http://localhost:8080/test1   (test1은 리턴된 매서드 위 @GetMapping("/test1")일 경우)
	  http://127.0.0.1:8080/test1

자바의 클래스를 웹으로 전달할 경우 자바스크립트의 객체로 변환된다.
ex)   {"name":"John Wick","score":40}

//게시글 목록 조회 api 경우
  //(GET) localhost:8080/boards
  @GetMapping("")
  public ResponseEntity<?> getBoardList(SearchDTO searchDTO){		
    // ResponseEntity<실제 보낼 body영역 자료형>

    try { 		// 본문내용, try{본문}, 소괄호없음
      System.out.println(searchDTO);
      log.info("게시글 목록 조회 기능 실행 중~");
      List<BoardDTO> list = boardService.getList(searchDTO);
	// 본문내용 그대로 넣으면 됨 하지만 리턴문은 ResponseEntity.status() 넣어주기
      return ResponseEntity.status(HttpStatus.OK).body(list);
	// status(HttpStatus.OK) = http상태가 좋다 = 상태번호 200
    	// status(HttpStatus.NOT_FOUND) = 상태번호 404(URL오류)
   	// status(HttpStatus.INTERNAL_SERVER_ERROR) = 상태번호 500 (자바오류)
    	// status(HttpStatus.CREATED) = 상태번호 201
    	// status(HttpStatus.NO_CONTENT) = 204
	// return할게 없으면 .body(자료형); 대신에 .build(); 넣고 끝내기

    } catch (Exception e){
      // try에서 오류 발생하면 catch 실행, catch (Exception e){}
      log.error("게시글 목록 조회 중 오류발생");
      e.printStackTrace(); // 오류 발생 위치 알려줌
      return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR).body("오류오류");
    }

  }
// 0. @Slf4j 어노테이션 넣기  (로그를 남길수 있는 어노테이션) (레스트컨트롤러 어노테이션 자리에)
// 1. try{ } catch(){} 적기
// 1-1 try{ } 안에는 본문 넣기
// 1-2 catch( ) 소괄호안에는 Exception e 넣기
// 2. catch() { } 중괄호에는 오류발생 위치가 들어간다 
// 2-1 catch { } 중괄호 안에 log.error( "오류 발생시 출력하고싶은 내용 입력" )
// 2-2 catch { } 중괄호 안에 e.printStackTrace(); 입력 - 오류발생위치 알려줌
// 2-3 catch { } 중괄호 안에 return문 작성
// 2-3-1  catch { } 중괄호 안에 return ResponseEntity.status(HttpStatus.상태).build(); 또는 .body("오류오류")
// 3. return문이 서로 다른 자료형일 경우 매서드의 자료형을 ResponseEntity<?>로 바꾼다.
